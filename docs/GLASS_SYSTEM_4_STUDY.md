## 4.0 新实现

### 1. 全表面圆角折射

- 保留 WebGL1、单共享 Canvas、共享背景纹理、圆角 SDF 和独立 DOM 文字。
- 对每个像素，按从气泡中心出发的射线计算真实圆角边界距离（直边和角部二次交点），得到 `radial = |local| / boundaryAlongRay(dir)`。
- 使用连续的透镜曲率函数在气泡整张表面产生有组织的纹理位移；不再只在 SDF 外边缘附近衰减。
- 加入**静态**低频波动项用于打破过于规整的形变。本轮没有时间动画，避免未测的持续 GPU 帧负载。
- 局部位移统一转换到共享背景的 `background-size:cover` UV 坐标，文字保持 DOM 渲染不受折射。

### 2. 明暗自适应边缘

- 采样背景亮度影响浅色／深色内侧光学修饰；亮背景减少发白，暗背景保留局部反光空间。
- 高光由外法线与两个光照方向决定，不做均匀整圈白色描边。
- 轻微内侧吸光配合两层**模糊** CSS 外投影形成空间层次。CSS 的可见实线边框仍为透明，Shader 是光学轮廓的唯一有色绘制者。

### 3. CLEAR / SMOKED 两套实验预设

- `CLEAR` 默认，优先清透与背景折射。
- `SMOKED` 增加低强度吸光与中性色衰减；两者共用几何、纹理与 Shader。
- 折射强度、内侧厚度、方向高光、表面波动可实时调节。

### 4. 背景与移动端

- 页面自带程序绘制的结构化柔和背景，可观察折射；它不是参考仓库受版权保护的图片。
- 继续支持用户从相册选择图片。浏览器本地处理，不上传照片。
- 沿用 3.0/P2.2 的 GPU 纹理像素预算、对象 URL 管理、ResizeObserver、上下文丢失 CSS fallback 和资源回收。
- 每个气泡绘制前启用 `gl.scissor`，只在实际气泡矩形附近执行片元着色，避免全画布四次完整覆盖。

## 初步验证与限制

**已完成的源码级检查：**
- 独立页面已创建；JavaScript 可解析。
- Shader 使用 `boundaryAlongRay` 与全表面形变而非仅边缘 `exp(-inside)`。
- `OES_standard_derivatives` 可用时正确注入 `fwidth` 抗锯齿分支；回退路径保留。
- CSS fallback、纹理上限、图片选择防竞态、WebGL 恢复处理、局部 `scissor` 路径均存在。
- 未修改 3.0 HTML 或正式产品仓库。

**仍需 iPhone Safari 实测：**
1. 首次加载显示 `WebGL · DPR … · fwidth AA`，四个气泡有完整折射。
2. 使用有直线／窗框的背景，对比 3.0：玻璃中央应有连续折射，非仅白边。
3. 换为用户自己的明亮照片、深色照片和横竖方向照片，检查背景/折射裁切是否一致。
4. 调节折射强度 0、默认和 100：中心变化连续、不出现断裂、黑块或纹理翻转。
5. CLEAR / SMOKED 切换，文字可读、亮区不过曝、暗区不形成黑色塑料厚框。
6. 页面滚动、缩放、横竖屏切换、后台恢复。
7. 检查多行气泡与短气泡的圆角、阴影和边缘是否自然；特别留意之前的角部锯齿。

**明确没有证明：** WebGL 着色器在真实 iPhone 编译成功、材质效果已经符合用户目标、性能／显存指标优于 3.0、动态波动可持续运行。以上需要设备实测；不能以代码检查代替。

## 后续方向

先拿到亮背景和暗背景的实机截图，用**同一张图片和相同的气泡尺寸**对照 3.0，再单独调整透镜强度、内侧明暗与阴影。不要同时改变多项；不要为了视觉体积重引入大面积白色填充。

等视觉方向得到用户明确认可，再单独处理复杂背景同步、长聊天列表稳定快照、可见性剔除和正式集成评估。**正式 UI 在这一切之前继续冻结。**
