# Glass System 4.2 · Optical Volume Study

状态：**独立材质实验，尚待 iPhone Safari 视觉验收。** 本轮基于已在用户 iPhone Safari 上显示 `GPU · fwidth AA` 的 4.1，保留 4.1 为对照，不覆盖 4.0、3.0，也不修改正式产品仓库。

## 实测输入及目标

2026-11-06，用户在同一樱花背景下上传了两张 iPhone Safari 截图：4.1 的「原图对照」（按钮显示「恢复玻璃」）与 4.1 的 WebGL CLEAR（按钮显示「原图对照」）。两个状态下画面均显示 GPU + fwidth AA，用户认为「感觉还行」。从截图观察，清透度与圆角方向已经可以保留，但透镜的结构感、边缘内侧反光与悬浮厚度仍较含蓄。

本轮目标只调整：

1. **透镜体积曲率**：保留中心清透度，在圆角表面的中后段加入独立的肩部折射区域，使背景线条穿过气泡时出现更明显但连续的变形。
2. **曲面反光**：把一道小范围反光绑定到模拟曲面法线，而不是在整圈边框叠白色轮廓。
3. **内侧厚度与环境距离**：在明暗自适应内侧吸光的基础上小幅调整两层柔软的 CSS 阴影。

参考视觉方向：`yanceydaisy/liquid-glass-note` 的 CLEAR 手机材质截图。参考仓库目前公开的是文档、图片、部分公式说明，未授予完整原创引擎复用许可。**本试验根据公开原理独立编写，不复制参考仓库 Shader 或资产，也不宣称逐像素复刻。**

## 4.2 光学方案

### 共享几何与透镜

- **完全保留** 4.1 的圆角 SDF `roundedDistance` 与射线交点 `roundedRayLength`，胶囊状气泡、圆角半径、文本布局都不变。
- 与 4.1 的单一光滑圆顶不同，本版将位移分成中心 `lensBody`、中外侧 `shoulder`、边界缓冲 `rimTail` 三项，它们都在半径 [0,1] 内连续变化。
- 中心 `lensBody=1.07*(1-r^1.7)`；肩部 `0.43*smoothstep(0.40,0.72,r)*(1-smoothstep(0.87,0.985,r))`；边缘缓冲 `0.07*smoothstep(0.72,1.0,r)`。
- 位移由 `p*profile*(102*power)` 给出，再叠加只在肩部明显、不会持续耗电的**静态**切向低频微扰。动态时间动画暂不加入。
- 和 4.1 一样，所有位移通过共享背景纹理的居中 cover 采样坐标，`原图对照`依然可以旁路所有光学修饰。

### 曲面光与厚度

- 保留 4.1 的一条亮背景变弱、暗背景更明显的细轮廓，以及只在局部方向出现的边缘高光。
- 新增由 `surfaceNormal` 导出的 **小范围曲面反光**：只在径向中外段和某个光源方向有非零贡献。避免整圈白边或全表面均匀漂白。
- 内侧暗部由 `bevel + shoulderShade` 组合；沿与光源相反的边缘方向衰减，明亮背景下减少吸光。
- 非 SMOKED 的 CLEAR **没有统一的奶白/粉色填充层，也没有模糊覆盖层**。文字由 DOM 绘制，保持清晰。
- CSS 只小幅加深原有的两层柔软投影；圆角 25 CSS px、可见边框绘制方式保持。

### 变更边界

- 新增 `docs/glass-system-42.html`，原 `docs/glass-system-41.html`、`40.html`、`30.html` 原样保留。
- 控件结构、预设 CLEAR/SMOKED、原图对照、GPU/降级状态标识、可上传背景均保留。
- 无外部背景资源请求；相册照片留在本机。
- 单 WebGL Context、GPU 纹理 500 万像素预算、按需刷新、scissor、WebGL Context 恢复路径未变。
- 不修改正式 `sin047/shen-liang-home`。

## 静态验证

- JavaScript 整体语法可解析；片元 Shader 组装后的源码中 `sd` 在 `fwidth(sd)` 之前声明，避免 4.1 首次出现的 `fwidth(d)` 编译错误。
- Shader 使用的 GLSL ES 1.00 语法不依赖循环时间、额外贴图、WebGL2 或第三方着色器。
- 数学采样验证：新旧版本在 `r=0.50` 处的折射规模近似相同，`r≈0.75–0.90` 肩部折射更明显；`r=1` 新位移保持很小，降低最终轮廓的采样跳变。
- GPU 运行指示与原图对照测试保留，能判断是新光学效果还是回退 CSS。
- 由于执行环境的浏览器无法获得 WebGL Context，**未取得真实 GPU 编译或运行截图**，不能将静态检查标为设备验收。

## iPhone Safari 实测清单

1. 先看画面右下角显示 `GPU · fwidth AA`，而不是 `CSS fallback`。如果失败，截图下方 `ERROR` 原文。
2. 选同一张樱花背景，对比 4.1 和 4.2，观察桥、建筑窗框、伞骨在中外侧玻璃中是否弯曲得更明显，而中间仍清楚。
3. 在 4.2 点击「原图对照」再恢复玻璃。边缘应出现连续透镜位移，不是平铺纹理或整圈白光。
4. 观察玻璃顶部/侧边是否只出现**局部**反光；确认不出现奶白、塑料白框、粗灰壳或黑色撕裂线。
5. 控件从折射 0 到默认（0.61）再到 1.00，留意边缘波纹/纹理翻折。如果变形太强，记录数值，不需要继续提高。
6. 换明亮与深色背景，以及 SMOKED 预设，确认自动明暗处理正常、没有明显闪白或黑边。
7. 滚动、缩放、横竖屏、更换相册图片、切换 App 后恢复，GPU 状态保持正常。

这轮将优先等待用户视觉反馈，不会将它认定为最终满意或直接接入正式 UI。


## 2026-11-06 · iPhone Safari shader compile failure and minimal fix

用户实测 4.2 截图显示 `CSS fallback · 未运行光学`，控制栏给出精确编译错误：`ERROR: 0:136: 'innerRim': undeclared identifier`。因此该截图是 CSS 降级样式，不是新版光学结果。

**根因：** 4.2 在更换内侧光学变量时，将 `innerRim` 改为 `bevel`，但是 SMOKED 吸收分支的 `float absorb=0.18+0.10*innerRim;` 没有同步更名。GLSL 编译器会检查整个片元 Shader，即使用户选择 CLEAR，也不能忽略 SMOKED 分支中的未声明符号。

**修复：** 4.2 HTML 中只替换一处 `innerRim` → `bevel`。这不改变本轮 CLEAR 透镜曲线、局部反光、透明度、圆角、布局或背景处理。原 4.1、4.0、3.0 保持不变。

**防回归：** 增加 `tools/check-glass-shader-identifiers.cjs`，静态提取 4.1 和 4.2 嵌入的 GLSL，检查基础与开启导数扩展的两条 Shader 源码路径是否存在未声明标识符。验证器对修复后代码通过；重新注入 4.2 的 `innerRim` 旧引用和 4.1 的 `fwidth(d)` 错误后，均能准确报告。这是**静态声明检查**，不等于真实 GPU 编译；需要 iPhone Safari 再次确认 GPU 状态。

**复测方式：** 使用既有 4.2 页面，画面右下角应显示 `GPU · fwidth AA`；如果仍显示 `CSS fallback`，将编译错误文本截图返回。确认成功后才评价材质，尽量在同一樱花背景下与 4.1 对比。
